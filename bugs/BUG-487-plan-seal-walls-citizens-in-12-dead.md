# BUG-487 The plan's seal walled 12 citizens in: plan build skips the reach check, close=door is overridden, LOCKED_OUT waits for a player
Status: fixed (offline, live-untested)
Severity: critical (12 citizens died of thirst, Pop 100 -> 88; the west farm and 8 beds cut off again the next year)
Found: 2026-11-05, Run 16b i2 Roadvises y399-y402 (`runs/run-16b/FR-BUGS.md` "KRITISCH, 12 Tote" and "plan check erzwingt Bypass-Wall; close=door wird ignoriert"; runtime `r16b3-roadvises-site97/` kern.log lines 1065-1131, cli.log 1800-1845, bp/y401s0b0.json, read only)
Module: `lua/dfllm/runner.lua` (`sync_plan`, `Q.place_walls`, `Q.lockout_scan`), `dfpilot/cmd.py` (`seal_openings`, `audit_routes`), `dfpilot/plan.py` (`audit_gate`, propose), `dfpilot/wake.py`

## Actual
y399 `bp.place seal at=audit` was refused by the BUG-458 reach check ("would cut 1 off the main walk group (citizen 60,99,121) ... close with doors"). `plan propose` drew `seal@S1` on the same bypass every year (y399s0b0 60,99,121; y400 64,99,121; y401 60,100,121), `plan check` said OK. After `plan apply` y401 the kernel built the wall at 60,100,121 (`bp/y401s0b0.json`: one cell `Cw`, params `at "60,100,121 floor wall"`, close auto): "locked out: our wall at 60,100,121 shuts 12 citizen(s) and farm 48,93,121" (kern.log only), 12 citizens on walk group 4729 (farm, beds) with thirst 54k-75k died. y402: with `p.close=door` plan check was OK and the kernel built a wall again (`Cw` 61,100,121).

## Root causes
1. `lua/dfllm/runner.lua sync_plan` (line ~424): a plan build goes `plan.reload` -> `sync_plan` -> `register` and never calls `Q.place_walls`, the reach check only the `bp.place` verb made (cli.log: the y399 `bp.place` was refused, the y401 plan build was not a `bp.place` at all, commands.log shows `plan.reload` and then `runner act.quickfort run 60,100,121`).
2. `dfpilot/cmd.py seal_openings` (the audit entry, `"piece": o["piece"]`): the audit route carries the piece `wall` (`x,y,z floor wall`), and `defense.seal_pieces` takes `want = o["piece"] or close`, so an explicit `close=door` never reached an audit tile.
3. `plan.audit_gate` / `propose` had no knowledge of the kernel's refusal: the kernel was the only one who knows the citizens' walk group, and it told nobody except the caller of `bp.place`.
4. `lockout_scan` walked `sorted()` (the open projects only): the walls of a finished project (`S.rt.ow`, kept for exactly this) were never looked at again, and a found wall only raised a question (DECISION_NEEDED `locked_out`, A) that waited for a player (12 died in the 5 days of waiting).

## Fix
- `sync_plan`: a plan build of a seal / repair goes through `Q.place_walls`; where it refuses (cut, partial or unknown reach) the walls become doors (`Q.walls_to_doors`: `Cw...` -> `d...`, materials wall -> door, kern.log `plan build <id> (seal): N wall(s) built as doors: <refusal>`). A wall on a ramp top cannot be a door: the build is not queued, PROJECT_BLOCKED says so. `bp.place` still refuses (round 28). The door that quickfort cannot place (no wall beside it) walks the BUG-458 guard (the door stays, the door is made at the workshop).
- New event WALL_REFUSED (B; `at` tiles, `n`, `how` place | plan | door, `proj`, `why`; once a game day per tile): every refusal of the reach check leaves it, so the plan layer knows the tile.
- `cmd.wall_refusals` reads it (a game year, cleared by a seal project that finished after the refusal); `audit_routes` returns `cut` (open audit walls the kernel refused) and `doored` (a door stands where the wall would cut). `seal_openings`: an explicit `close=door|grate|bars` or a refusal beats the audit's `wall` piece on a floor tile (note says so), and a refused tile gets no `nodoor` wall-instead.
- `plan check` (`audit_gate`): ERROR when a seal build that walls a refused tile has no `p.close=door`; with `close=door` it is accepted and honoured; the fix text drafts `close:door`; a standing door is a warning, not a forced wall (the audit counts walls only: decide by hand). `plan propose` and follow's `_request_seal` draft / place `seal at=audit close=door` there.
- `lockout_scan` looks at every project (finished ones too) and takes our wall down at once (`Q.lock_reopen`: `bp.cancel reopen` = quickfort undo; a running project's document cell becomes a door; a finished project's tile gets a `repair` project with the door cell; `economy.seal_doors` the door task). DECISION_NEEDED `locked_out` stays class A and says so (`reop` = walls taken down; wake hint "nothing to do but watch it"). `runner.CFG.lock_reopen = false` = the question only (round 28). A project that finishes with walls is looked at on the next run.
- Not changed: gate.lua, bridge logic.
