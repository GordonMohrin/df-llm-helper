# BUG-851 The gamelog reader looked once per fresh economy run: at 530-860 ticks/s that is every 10-20 game days, the source fell back to `report` and the gate never fired
Status: fixed (offline, live-untested)
Severity: high
Found: Run 17d i4 Girderroots (main 55e827ed, E:/DF-test4), 24.11.2026 23:50 (lead's Nachtrag 23:50 in `leitung/neu3/LIVE-DIAGNOSE-2026-11-24.md`): kern.log `DF cancel lines seen in window: 2 (source report; gamelog readable but no new line for -1 d; 2 reports since load)`, later `... window: 0 (source report; ... no new line for 11 d; 6 reports since load)`, `why brew` dfh `no new line for 9 d`. gamelog.txt grew 272182141 -> 272496144 bytes in ~100 game days, ~110 of 400 lines were 'Needs empty food storage item' cancels, `cx_gate` never reached 5.
Module: `lua/dfllm/economy.lua` (`M.watch`, `M.watch_every`, `M.gl_poll`, `M.cw_source`, `M.cw_health`, `M.step`), `lua/dfllm/gamelog.lua` (`G.poll`), `lua/dfllm/cancelwhy.lua` (`C.note`), `config/baseline.json`, `dfpilot/fairplay.py`

## Root cause
`M.step` called `M.gl_poll` only at the start of a FRESH run (`not ctx.cont`). A fresh run starts at most every `every.ticks` (1200) times the demotion factor times the load stretch, and a run itself spans many continuation frames under pacing. At 530-860 t/s one game day is ~1.5-2 s, so two fresh runs lie 10-20 game days apart. `M.cw_source` called the file the source only if the last look that saw a new line was at most `GL_FRESH` (3 game days) old: between two looks that was nearly always false, so the source was `report` (the lossy eventful path, 2-6 reports since load) and `cancel()` counted the reports instead. The reader's tally of the 7-day window was therefore empty or tiny whenever the economy looked at it. Per look the budget was one 128 KB chunk.

## Measured cadence
kern.log has no per-run marker, so the distance is read off two sources. (1) perf.csv of i4 (247 samples at >= 500 t/s in PEACE): one 30 s sample spans 17.6 game days on average and every sample holds economy time (mean 45 ms), i.e. economy is paced to roughly one fresh run per sample or fewer. (2) The stall lines: the reader's last look that saw a new line lay 9-11 game days before a stall line written inside the same economy run (the lag equals the run's own length plus the gap since the previous fresh run). So 10-20 game days lie between two fresh runs at that speed, against a 3 game day freshness limit and a 7 game day window.

## Fix
- `M.watch` / `M.watch_every = {ticks = 600}` (half a game day): the kernel's own optional pass (BUG-136, `kern.lua` frame loop: its own tick clock, run before the step check of the frame, never paced, never demoted, not stretched by the fort-size load, also while a run is in hand, not while paused). The look is now in game time at any speed: at most half a game day between two looks at 50 t/s and at 800 t/s alike. Cost per look: one `io.open`, a seek to the end, 64 bytes of head, then only the new bytes (about 3 KB per game day live, ~12 KB per look in the flood of the test) and a cheap prefilter (`line:find(' cancels ', 1, true)`) before the parser. `M.step` no longer polls.
- Per look up to `economy.cancel.gamelog_chunks` (default 8, 1..64) reads of `gamelog_bytes` (131072): 1 MB per look, equal to the library's backlog limit, so what a look can read it never skips. `s.behind` = bytes still unread after the look, `s.lastlook` = {lines, cancels, bytes}.
- The lines of a look are grouped by job kind and reason before they enter the tally (`CW.note(..., n)`, stamped with the game tick of the look): one write per kind and reason, not per line (1500 'Drink: Well dry.' lines cost one write). The existing caps stay (14 days, 40 kinds a day, 8 reasons a kind and day, `(other)` beyond).
- Source: `M.cw_source` is `gamelog` whenever the file is readable (state `ok`), `report` only when it is unreadable, missing, switched off or not started. A quiet log is no reason to fall back; `GL_FRESH` is gone. The report handler still counts only when the source is `report` (no double count).
- Health text: `DF cancel lines seen in window: N (source gamelog; 119 looks, 0 B behind, 13500 lines read, 10800 cancels[; the log is quiet (no new line for 19 d)])`, or `(source report; gamelog missing: ...; K looks; R reports since load)`: looks made, bytes still behind, source. 'quiet' is information only.
- The gate compares the cancels of the last 7 game days (`cx_gate` unchanged): once the reader keeps up, that rate does not depend on when the economy looks at it.
