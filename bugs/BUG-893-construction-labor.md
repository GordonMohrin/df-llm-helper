# BUG-893 A wall / floor construction has no labor in the kernel: '12 idle holders', 'labor unread', 'why job:' reads it as a Farmers workshop, 'no item' with an item attached
Status: fixed (offline, live-untested)
Severity: high (the kernel counted every adult as a builder and never put the Building construction labor on; the texts pointed the player nowhere)
Found: Run 17d i4 Girderroots (SEAL_STUCK #21972 'job 1733178 not suspended, no builder has taken it; 12 idle holders reach it, DF did not assign it'; PROJECT_BLOCKED 'labor unread'; `why job:1733178 --raw` 'ws 19342 workshop:Farmers ... derived labor: PROCESS_PLANT'; DECISION_NEEDED #22160 / #22161 'no item' while an item is attached)
Module: `lua/dfllm/economy.lua` (`M.BUILD_LABOR` ~l.13981, `M.hands`, `M.build_state`, `M.dedicate`, `M.LABOR_MIN`), `lua/dfllm/jobwhy.lua` (`J.shop`, `J.labors`, `J.BUILD_LABOR`), `lua/dfllm/dfraw.lua` (`R.job`, `holders_head`), `lua/dfllm/runner.lua` (`Q.cls_of`), `lua/dfllm/act.lua` (`labor_set` `construction`)

## Cause
(1) `M.BUILD_LABOR` (BUG-329) had no key for `Construction` (nor `Road`): `M.hands` set `has = true` for every adult, so the texts counted 'idle holders' of a labor nobody had read and `nobuilder_why` never said 'no citizen holds it'. A wall is built with the Building construction labor (`df.unit_labor.BUILD_CONSTRUCTION`, DF's labor 'Construction': BUG-009 'all adults have BUILD_CONSTRUCTION and MASON enabled', BUG-745 `M.wall_builders`; no DF structure source is installed next to the game, the name is the one the repo already reads live). (2) `JW.shop` took ANY holder building for a workshop: the construction type number of a wall (`building_constructionst.type`) was read as a workshop type, 'Farmers', whose labor is PROCESS_PLANT. (3) `Q.cls_of` called every job suspended by buildingplan 'no item', also with an item attached.

## Fix
`BUILD_LABOR.Construction = 'BUILD_CONSTRUCTION'`, `Road = 'BUILD_ROAD'` (+ `LABOR_WORD`); `M.hands` flags a labor it could not read (`unknown`) and the texts then say 'N idle adults (its labor is not known)' instead of 'holders'; `JW.shop` names a building that is no workshop or furnace by its own type (`building:Construction`, `s.kind`), `J.labors` knows the labor of such a ConstructBuilding job (`J.BUILD_LABOR`), `why job:` prints 'holder building is a Construction, not a workshop: DF needs the labor BUILD_CONSTRUCTION' and the holders as 'N holder(s) of M citizens'; the kernel already manages labors (`act.labor_set`, `M.dedicate` for Furniture hauling / Mechanics): `construction` (BUILD_CONSTRUCTION, only on) is added and a raised building job whose labor has fewer than `M.LABOR_MIN` (3) holders gets it put on for one more idle adult a day (ORDER_STUCK kind worker 'only N held BUILD_CONSTRUCTION: labor on for unit U'); `Q.cls_of` says 'no item' only when nothing is attached. `labor.set` accepts `construction` (schema enum).

## Tests
`tests/lua/test_bug892_893_bau.lua` (holders counted for Construction, 'adult' for an unknown labor, `nolabor` text, 'no item' only without an item, the 3-holder rule, `why job:` for a wall: key, labor, text, holder count); `tests/lua/test_bug546_547_acts.lua` (error text lists `construction`).

## Live-Erwartung
`why job:<wall job> --raw` prints 'holder building is a Construction, not a workshop: DF needs the labor BUILD_CONSTRUCTION' and 'labor BUILD_CONSTRUCTION: N holder(s) of M citizens'; SEAL_STUCK / PROJECT_BLOCKED say 'labor N/M' (not 'labor unread') and, when nobody holds it, 'no free adult citizen has the labor Building construction (walls, floors) on (0 of M; a work detail grants it)'; with fewer than 3 holders and a raised wall job, one adult a day gets the labor (kern.log 'Labor BUILD_CONSTRUCTION on for unit U'). NOT promised: that a work detail of DF does not switch the labor off again, nor that the wall is built when its material is missing.
